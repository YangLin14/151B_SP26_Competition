## 你隊友 plan 的判斷

### 有效的部分

這些是合理的：

```text
1. 先 benchmark starter baseline
2. 做 prompt fixing
3. 做 self-consistency majority voting
4. 做 overfit smoke test
5. 記錄 GPU、runtime、learning rate、batch size、optimizer
6. 補 report 裡的 table / abstract / references
```

Self-consistency 本身是有文獻支持的：原始方法就是 sample 多條 reasoning paths，然後對 final answer 做 majority vote。([arXiv][3]) 所以這不是亂搞。

Unsloth 也不是幻想。Hugging Face docs 說 Unsloth 是 fine-tuning / RL framework，支援 Qwen 等模型，透過 patch Transformers 內部方法來加速訓練、降低記憶體使用。([Hugging Face][4]) TRL 的 SFTTrainer 也支援 PEFT/LoRA adapter training，通常 adapter training 會用比較高的 learning rate，例如約 `1e-4`。([Hugging Face][5])

### 爛的部分

你隊友 plan 的問題是：**它把 advanced stuff 放太前面。**

尤其是這幾句：

```text
WRITE CODE: Precise Model Loading with BF16 + Unsloth
WRITE CODE: SFT Trainer
k = 16 majority voting
```

這些不是第一步。你現在連 full baseline accuracy 都還沒有。沒有 baseline，你做 BF16 / Unsloth / SFT 只是亂試。老師問一句「improved from what to what？」你們就卡住。

還有更大的問題：如果你用 `public.jsonl` fine-tune，然後又在同一個 `public.jsonl` 上報 accuracy，這個結果**不乾淨**。那叫 train-on-test，不是 validation。你可以用 public set 切 train/dev，例如 80/20；或者只把 public accuracy 當 Kaggle-style dev score，但 report 裡要誠實說明。

## Step 7：做 self-consistency，但先 k=3，不是 k=16

你隊友說 k=16。理論上可以，但現在太貴。k=16 是 16 倍 inference cost。你應該先做：

```text
k = 3
k = 5
k = 16 only if k=3/k=5 actually helps
```

先加 answer extraction：

```python
from collections import Counter
import re

def extract_boxed(text: str) -> str:
    """
    Extract the last \\boxed{...} content.
    Handles simple boxed answers. Good enough for first pass.
    """
    matches = re.findall(r"\\boxed\{([^{}]*)\}", text)
    if matches:
        return matches[-1].strip()
    return ""

def normalize_vote_answer(ans: str) -> str:
    ans = ans.strip()
    ans = ans.replace(" ", "")
    ans = ans.replace("$", "")
    ans = ans.rstrip(".")
    return ans

def majority_vote(responses):
    answers = [normalize_vote_answer(extract_boxed(r)) for r in responses]
    valid = [a for a in answers if a]
    if not valid:
        return responses[0], "", Counter()
    counts = Counter(valid)
    winner, count = counts.most_common(1)[0]

    # return one response that had the winning boxed answer
    for r in responses:
        if normalize_vote_answer(extract_boxed(r)) == winner:
            return r, winner, counts

    return responses[0], winner, counts
```

然後做 k samples。最簡單方式：把每個 prompt 重複 k 次。

# Step 8：你要寫一個 batch generation loop

現在 notebook 直接把所有 prompts 一次 tokenize。full public set + 32768 tokens 可能爆記憶體。用 batch。

```python
GEN_BATCH_SIZE = 2  # A30 上先保守。能跑再改 4 或 8。

def generate_responses_transformers(prompts, batch_size=2):
    all_responses = []

    for start in tqdm(range(0, len(prompts), batch_size), desc="Generating"):
        batch_prompts = prompts[start:start + batch_size]

        inputs = tokenizer(
            batch_prompts,
            return_tensors="pt",
            padding=True,
            truncation=True,
            max_length=16384,
        ).to(llm.device)

        with torch.no_grad():
            output_ids = llm.generate(
                **inputs,
                max_new_tokens=MAX_TOKENS,
                temperature=0.6,
                top_p=0.95,
                top_k=20,
                repetition_penalty=1.0,
                do_sample=True,
                pad_token_id=tokenizer.eos_token_id,
            )

        prompt_len = inputs["input_ids"].shape[1]
        for out in output_ids:
            new_tokens = out[prompt_len:]
            text = tokenizer.decode(new_tokens, skip_special_tokens=True).strip()
            all_responses.append(text)

    return all_responses
```

然後：

```python

```

## 如果你真的要做 SFT，正確做法是這樣

### 不要直接用整個 public set train 然後又在 public set 上報結果

做 split：

```python
import random

random.seed(42)
shuffled = data[:]
random.shuffle(shuffled)

split = int(0.8 * len(shuffled))
train_data = shuffled[:split]
dev_data = shuffled[split:]

print(len(train_data), len(dev_data))
```

Report 裡要說：

```text
We split public.jsonl into 80% training and 20% held-out development for fine-tuning experiments.
```

### SFT target 要小心

你們 public set 只有 ground-truth answer，不一定有完整 reasoning trace。你如果把 target 設成：

```text
\boxed{answer}
```

模型會學會短答案，不一定學會 reasoning。這可能對 competition 有用，也可能破壞 thinking style。

比較安全的 SFT target：

```text
We need solve the problem and provide the final answer.
\boxed{answer}
```

但老實講，這不是很強。真正高品質 SFT 需要有 step-by-step solutions 的公開數學資料集。你們可以之後用 MATH/GSM8K 類資料，但那是下一階段。

# 關於 BF16 + Unsloth：你隊友講法要修正

他說：

```text
Rewrite model loading to use torch_dtype=torch.bfloat16 and integrate Unsloth fast-loading API to replace default BitsAndBytes quantization.
```

這句混在一起不精準。

正確講法：

```text

```

不要把 baseline 直接改掉，否則你沒有 control。

你的 experiments 應該是：

| Run            | Model loading      | Training         | Inference     |
| -------------- | ------------------ | ---------------- | ------------- |
| Baseline       | BitsAndBytes INT4  | none             | single sample |
| Prompt v2      | BitsAndBytes INT4  | none             | single sample |
| Prompt v2 + SC | BitsAndBytes INT4  | none             | k=3/k=5 vote  |
| BF16 ablation  | BF16               | none             | single sample |
| SFT/QLoRA      | Unsloth LoRA/QLoRA | train split only | single or SC  |

這樣才科學。
